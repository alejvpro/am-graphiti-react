### Runtime flows and prioritized findings

1. **Unauthenticated HTTP writes deserve priority.**  
   The Mac bridge starts on port **7305**, exposes permissive CORS, and shows no authentication or TLS setup in the inspected application handlers. GET routes `/rate`, `/loved`, `/energy`, `/mood`, and `/tag` write Music metadata. `/ip`, `/now_playing`, and `/song_info` are informational handlers. External reachability was not tested.  
   Evidence: [AppDelegate.m](/Users/alejandroveloz/Documents/alej-music-osx/alejmusic/AppDelegate.m:763).

   The Node API likewise shows permissive CORS and no incoming authentication middleware. GET `/tracks/:catalog_id/dismiss` writes MongoDB; GET `/tracks/:catalog_id/add` writes Apple Music before updating MongoDB. Partial failures can leave those systems inconsistent.  
   Evidence: [index.js](/Users/alejandroveloz/Sites/am-playless-api/index.js:1), [controller.js](/Users/alejandroveloz/Sites/am-playless-api/controller.js:86).

2. **Credential storage and error logging need follow-up.**  
   The supplied scheduling evidence represents a plaintext database password; rotation and safer storage remain follow-up actions. API/script `.env` files and the developer signing key have mode **0644**, permitting other local users to read them where directory permissions allow. A second signing-key copy exists under the legacy `soft-keep/generator` directory.

   The token generator signs ES256 developer tokens for **180 days**. Documented renewal manually updates the frontend, authenticates through MusicKit, and copies tokens into two `.env` files. Frontend code prints authentication tokens; collectors/API handlers log whole Axios errors, which can include credential-bearing request headers. Secret values were not reproduced.  
   Evidence: [utility instructions](/Users/alejandroveloz/Sites/am-utilities/README.md:3), [generator](/Users/alejandroveloz/Sites/am-utilities/apple-music-token-generator/generate.js:11).

3. **Collector completion does not mean complete success.**  
   The playlist collector reads Apple Music catalog playlists, matches MongoDB records by catalog ID, and updates source membership/date ranges and discovery records. It continues after playlist retrieval failures, does not follow track pagination in the inspected function, does not await `insertOne`, and exits with status **1 even after normal completion**.  
   Evidence: [collector](/Users/alejandroveloz/Sites/am-playless-api/scripts/collectTracksFromAmPlaylist.js:438).

   Recent logs show runs completing October **17, 24, and 31**, with processing/insertion messages, but **Vibes retrieval failed with authorization errors in all three**. Older representative logs show recurring 401/Unauthorized periods across multiple years. Logged insertion counts are application reports, not independently verified database writes.

4. **Matching and caching can produce incorrect or stale results.**  
   The Mac bridge searches Music by name, then compares lowercase name, artist, and album exactly. `/song_info` rejects multiple matches, while mutation handlers select the first match whenever at least one exists. Missing query values can also reach dictionary construction without validation.

   The `caching` branch retains up to 100 search results, including serialized metadata, without visible invalidation after writes. Subsequent reads can therefore return stale metadata.  
   Evidence: [matching/cache](/Users/alejandroveloz/Documents/alej-music-osx/alejmusic/AppDelegate.m:1148).

5. **HHH collection has recent positive evidence; DNS logs require careful interpretation.**  
   HHH uses Reddit credentials from the scripts environment, searches `/r/hiphopheads`, filters title and author, and writes sanitized timestamp/title Markdown filenames relative to `scripts/`. It stops at an already-existing matching file. The October 31 log records creation of the October 30 post and completion at **10:00:02**. Historical samples include errors, including a 403.  
   Evidence: [scraper](/Users/alejandroveloz/Sites/am-playless-api/scripts/findHhhNewMusicFriday.js:21), [HHH log](/Users/alejandroveloz/Desktop/hhh-log.txt).

   DNS uses `curl` against Namecheap’s dynamic-DNS service. Recent sampled responses report `ErrCount=0` and `Done=true`. The word “error” appears inside response markup and must not be counted as a failure by itself. Log modification times do not establish current DNS correctness.  
   Evidence: [DNS script](/Users/alejandroveloz/Desktop/dns.sh:19).

The bridge log contains ordinary search/tagging activity, no-match results, and numerous “Default handler” entries. Its timestamps contain only time of day, and default-handler logging omits the request path and client. Those entries cannot establish their origin or compromise. No crash was demonstrated by the bounded samples.
